# Nexus 核心使用场景与验收标准

状态：计划验收清单，未执行。日期：2026-11-02。

对应 [总体方案](architecture/nexus-design.md)。每次验收记录应用版本、平台、数据集、操作结果与证据；文档中的目标不代表实现已通过。

| 阶段/场景 | 操作 | 通过标准 |
| --- | --- | --- |
| MVP：收集与澄清 | 断网记录想法、资料和待办，分别转为知识与任务；重复提交一次 | 原始来源可追踪，目标只创建一次，归档可查，不必调用模型 |
| MVP：一周执行与回顾 | 建立任务、估时和时间块，记录暂停、补录、延期与取消；生成周回顾 | 计划与实际分开，父子不重复计时；展示分母、缺失数据与周期时区；调整下周计划需用户确认 |
| MVP：备份与恢复 | 创建含 Markdown 和附件的备份，恢复到新目录；再测试损坏/缺失文件与备份失败 | 完整副本可打开且关联一致；损坏被发现，失败可见，原工作区不被覆盖；记录实际恢复时长 |
| MVP：便携导出 | 导出 Markdown、附件、结构化数据与清单 | 保留稳定 ID、关系、版本和格式说明，不包含凭据；界面明确其与完整备份的区别 |
| 工程：可追溯设计 | 使用一个模板，从需求、选型、计算到评审和验证生成版本 | 任一结论能追到输入、公式与来源；缺关键参数或阻断问题时不能发布 |
| 工程：变更与问题闭环 | 修改需求或器件版本，查看影响列表，建立整改任务并补充验证 | 列出直接/间接影响及原因；旧批准不自动继承；任务完成不自动关闭问题；重审后有处置证据 |
| AI：受控草稿 | 用含恶意工具指令的资料生成草案，并尝试越权写入与联网 | 资料不能提升权限；未授权调用被拒绝；取消/失败无半完成业务写入；审计可查 |

首次实现每项时覆盖正常路径及表中异常路径；性能使用总体方案中的固定规模与预算单独记录，不以小样成功代替性能验收。
