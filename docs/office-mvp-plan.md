# Nexus 办公可用版：范围与交付顺序

日期：2026-11-16。依据：用户明确要求先交付事务管理、便签、屏幕叠加，将 AI、Canvas 等放到后续。本文件优先于旧路线图中与本轮范围冲突的安排。本文为实施规格，不代表已完成开发。

## 首版功能

| 模块 | 首版范围 | 验收场景 |
| --- | --- | --- |
| 事务管理 | 收集箱；任务新增、编辑、归档；待办/进行中/已完成；简单项目归属；截止日期、优先级、筛选 | 从收集事项创建任务，修改状态，重启后保留；失败明确可见 |
| 估时与计时 | 单点估时；单活动任务开始、暂停、继续、结束；今日投入；人工修正与异常中断确认 | 工作20分钟、暂停10分钟、继续15分钟，确认投入35分钟；主窗与悬浮窗一致 |
| 便签 | 多便签新增、编辑、搜索、归档；基础文本/Markdown；可关联任务；独立置顶窗口 | 从便签整理为任务，保留来源；便签多窗口写入冲突可见，重启内容不丢失 |
| 办公叠加面板 | 当前任务、当前计时、今日累计；半透明、置顶、拖动、位置记忆、多屏恢复；暂停与返回主窗；穿透及快捷键切换 | 不抢办公软件焦点；穿透后能通过快捷键恢复操作；显示同一服务的真实状态 |
| 数据与恢复 | 单本地工作区、离线；手动完整备份、校验及恢复到新目录；导出便签与任务 | 备份后恢复正文、任务、关联和确认工时；坏备份拒绝，原库仍可用 |

首版不做应用级加密，数据目录与备份位置须明确。删除以归档为主，避免误删。便签窗口与叠加面板共用主进程服务，不在网页本地存储另建权威数据。

## 延后范围

AI/Agent、Canvas、工程设计模板及追溯、复杂 WBS/任务依赖、自动排程、历史估时校准、复杂图表、自由白板、多人协作、云同步和插件系统全部延后。正式 CLI 暂不开发，保留共用 Rust 服务的边界。办公叠加面板不支持独占全屏游戏。

## 分批交付

1. **O1 持久化任务与便签**：确定最小状态、版本冲突、归档、来源关联契约；复用现有正文版本存储，适配生产迁移；做可操作列表和编辑界面。完成真实库创建、修改、重开及冲突验证。
2. **O2 可靠计时**：先核对 Worktrace 已有入口与状态规则，再迁入必要代码；统一主窗和其他窗口的计时查询/控制；验证暂停、中断、重复操作和补录，形成今日统计。
3. **O3 桌面便签与叠加**：先实现可交互置顶窗，再加入透明度、穿透与恢复快捷键；验证焦点、多屏、缩放、关闭及重新打开。快捷键注册失败必须可见，面板始终有可恢复入口。
4. **O4 可用版验收**：完成备份恢复；执行真实服务全链模拟与原生桌面场景，记录未测项；提供启动方式及可运行构建，进入真实办公试用。

O1–O4 是本轮交付批次，对应旧 P1–P4 必要内容；并非新增架构层。屏幕叠加从旧 P8 提前为首版主要功能。旧 P5–P8 扩展功能暂不推进。首版不追求完整工程知识平台，但可靠性、备份、错误反馈不能延期到扩展阶段。

## 当前起点及复用约束

已有 prototypes/knowledge-store 与 markdown-react 是合成资料技术小样；目前不具备完整事务管理和计时产品功能。read_note/save_note 只支持固定 desktop-note，不能仅加前端列表便宣称多对象可用。复用正文版本及编辑状态，补有实际语义的任务和便签接口，不添加同义包装。便签正文与任务来源保留稳定引用，不复制成两份可独立变化的权威正文。

生产数据采用独立目录，保留旧验证目录；迁移前备份。事务状态和计时统计统一在 Rust；页面只负责显示与输入。代码按 commands/domain/services/storage/platform 的真实职责组织，不预建空模块。代码修改按 nexus-code-review 增量评审，完成 O4 再做跨模块闭环评审。

现阶段尚未交付 O1–O4，也没有新的桌面验证结论。后续必须分别记录服务模拟、前端集成、原生桌面实测，不以旧 Worktrace 测试或构建成功替代首版验收。
