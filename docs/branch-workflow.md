# Nexus 分支与发布约定

日期：2026-11-02。项目开发目录：`D:\work_space\codex_workspace\Nexus`。

| 分支 | 身份 | 收录范围 |
| --- | --- | --- |
| research | 研发资料 | 调研、方案、实验记录、设计草案、评审、开发计划与验收证据 |
| dev | 测试版 | 开发中的应用源码、必要设计与用户文档、自动化测试；形成测试版本 |
| main | 发行版 | 从 dev 验证后晋级的稳定源码、必要文档与发布说明 |

后续在 Nexus 中开发；research 为资料工作分支，业务代码在 dev 开发。main 当前仅有初始化提交，不表示已存在可发行的软件。三个分支初始建立不代表完成测试或发布。

## 工作流

1. 需求、调研与设计在 research 留档，明确已确认、待议及实现状态。
2. 实现前将适用的已确认规格同步到 dev；只同步需要的文件或独立提交，不将整个实验资料分支自动合入源码分支。
3. 在 dev 开发与验证，重要修改记录范围、测试及局限；测试版使用预发行标签，例如 `v0.1.0-beta.1`。
4. 满足版本验收后，将选定 dev 提交通过审查合入 main，建立正式标签，例如 `v0.1.0`。发行步骤按当次授权执行。
5. 将实现结论、版本和验收证据回填 research，保留历史设计，不用新结论抹除旧决策。

## 提交与产物

研发资料是可审查的项目材料，不包含凭据、个人工作数据库、私有原始资料、模型权重或构建缓存。附件提交前检查敏感内容和体积；安装包与二进制优先作为发布附件管理，不长期累积在 Git 历史。

main 禁止直接日常开发；建议远程开启分支保护和必要检查，目前尚未配置，不将文档约定视为已启用技术保护。分支命名为项目用途约定，不引入额外长期分支。
