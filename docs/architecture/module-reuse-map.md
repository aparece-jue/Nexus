# Worktrace 接口复用初步映射

日期：2026-11-02｜固定来源：7b9cd47ee7e1b5d41a8a1403c9cbb21d9a6feb62｜状态：迁入前评估，尚未迁入源码

| 现有入口/模块 | 处理方式 | 必要变化 |
| --- | --- | --- |
| src/ipc.ts、types/ipc.ts | 优先沿用现有命令名、请求形状和错误/版本原语 | 新业务字段同步 Rust/TS 契约和测试，不添加同义命令包装 |
| state/domainState.ts | 沿用缓存失效与 epoch/revision 机制 | 让新增知识视图接同一失效入口，不另建权威状态 |
| commands/tasks.rs → services/catalog | 保留现有任务入口和校验职责 | 状态与 entity ID 对齐后定稿；不能将 capture 澄清语义硬塞入原任务命令 |
| services/timer、platform/clock | 适配复用，保留对应回归测试 | 保留毫秒精度、运行态边界和恢复语义 |
| services/stats | 沿用后端统一统计与区间裁剪 | 回顾补知识/成果关联，不在前端重复聚合 |
| services/backup、storage | 适配现有机制 | 纳入正文、附件与清单；候选校验及回滚仍复用，不建立第二套数据库备份入口 |
| 现有页面和 Ant Design 主题 | 按需要逐页迁入 | 清理无调用演示与重复 UI 依赖，按页面分包 |
| 知识版本、通用收集条目与对象关系 | 新增必要业务能力 | 旧项目无对应完整语义；不能只为避免新接口而混淆领域 |

以上不是无条件复制许可。原项目 Apache-2.0 文本已读取，文件级声明、依赖许可、适配后的接口一致性仍需核对。抽象只为实际职责和复用而建立，不新增通用 Manager/Provider 链；复用不能绕过领域校验或改变数据权威。
