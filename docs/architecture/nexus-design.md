## 2. 产品定位与边界

Nexus 是连接工程知识、设计成果和个人执行工作的本地桌面工作平台。核心闭环：知识复用 → 设计决策 → 任务执行 → 验证与复盘 → 知识更新。

个人单机优先，初期不建设多人协作、企业权限、多租户、云同步或通用插件市场。AI 提供草案与建议，工程批准和执行权由用户掌握。

| 模块 | 负责 | 边界 |
| --- | --- | --- |
| 知识 | 文档、器件、参考电路、规范、来源 | 不拥有任务状态 |
| 工程设计 | 需求、选型、计算、版本、评审、验证 | 不直接批准自己的输出 |
| 事务 | GTD 收集、项目、WBS、依赖、时间块、工时 | 不复制知识正文 |
| 效能分析 | 历史基线、估时偏差、容量预览 | 派生视图，不另建事实源 |
| 可视化 | 架构关系、白板、布局 | 画布位置不充当业务关系 |
| Agent | 检索、规划、工具提案与受控执行 | 不能绕过业务校验或直接写库 |

## 3. 技术选择与系统架构

延续预期的 Tauri + React + TypeScript + Rust 路线，采用单进程模块化单体；无需微服务、消息中间件、图数据库或独立 Python 服务。实际代码位置确认后再核对兼容性。

调用路径：React 页面 → 类型化 Tauri commands → Rust 应用服务 → 领域校验 → SQLite/附件存储。Agent 与人工操作共用应用服务。数据库、凭据、文件访问和网络策略由 Rust 边界统一控制。长任务后台执行，提供取消、进度、超时和失败恢复；禁止在 UI 线程执行索引或推理。

| 能力 | 建议 | 引入条件 |
| --- | --- | --- |
| UI/工作区 | Ant Design、Dockview | 若现有项目已用则保留，否则先验证必要性 |
| 持久化/搜索 | SQLite + FTS5 | 核心；先验证目标构建包含 FTS5 |
| 文档/附件 | Markdown、普通本地文件 | 元数据与内容版本由应用统一管理 |
| 架构/白板 | React Flow、Excalidraw | 分阶段按需引入，定义独立序列化版本 |
| 日历/统计 | FullCalendar、ECharts | MVP 可先用列表排程和基础统计 |
| AI | 模型适配接口；Ollama 或 llama.cpp 可选 | 不要求用户安装模型才能使用核心功能 |
| 版本 | 应用版本快照；Git 可选导出 | Git 不承担数据库备份 |

这些是候选方案，不是锁定依赖。许可证和成熟度尚未在线核验，也无锁文件可查；不得将上表视为许可证审计结论。采纳前记录精确版本、官方 LICENSE、传递依赖、商业/高级功能条款、维护与安全状态。特别核对日历高级资源排程、画布嵌入和分发条款；模型权重许可证须独立于推理程序核验。Rust 数据库库只选一种，通过迁移、事务与打包小样后确定。

## 4. 数据模型与一致性

SQLite 是结构化业务事实源；文档内容使用不可变版本文件，数据库保存当前版本指针与哈希。FTS、缩略图、向量和统计缓存均可重建。MVP 不支持外部编辑器双向同步；后续导入使用基准哈希检测冲突，不能静默覆盖。

所有对象使用应用生成的稳定 UUID，包含 created_at、updated_at、revision；时间戳保存 UTC，日历显示保留时区；时长统一整数秒，工程量明确数值、单位与容差。

| 表/集合 | 主要字段与关系 |
| --- | --- |
| entity | id、kind、revision、deleted_at；统一关联锚点 |
| project / task | entity_id；task.project_id、parent_id、status、type、complexity、uncertainty、energy |
| task_dependency | predecessor_id、successor_id；拒绝自依赖和环 |
| estimate | task_id、版本、乐观/最可能/悲观秒数、方法、样本数、创建时间 |
| time_entry / time_block | task_id、开始/结束、来源；分别表示实际工时与计划 |
| knowledge_item / component | entity_id、类型、结构化参数；正文引用 document_version |
| document_version / attachment | 所属对象、版本、相对路径、哈希、大小、格式 |
| entity_link | source_id、target_id、关系类型；两端外键指向 entity |
| design / design_revision | 所属项目、模板版本、状态、输入快照 |
| requirement / decision / calculation / verification | design_revision_id；需求、方案理由、公式输入输出、验证证据 |
| evidence | 来源版本、页码/章节、哈希、采集时间、适用条件 |
| agent_run / tool_action / audit_event | 运行状态、输入摘要、授权范围、工具结果、失败原因 |

每类对象与 entity 的创建/删除必须在同一事务；关联类型校验允许的两端类型，避免任意字符串关系失控。启用外键；WBS 拒绝循环和跨项目父子关系。项目删除默认归档，显式清除前检查引用。任务状态使用 inbox、next、scheduled、waiting、done、cancelled，父任务进度由子任务推导，父子工时不重复累计。

SQLite 事务不能覆盖文件系统：先写临时内容、校验哈希、原子移动至版本路径，再事务更新引用；崩溃遗留的无引用文件由恢复扫描识别并延迟清理。数据库迁移有版本号和迁移前快照，失败中止启动写入；升级前执行恢复演练。

## 5. 工程设计 AI 与追溯

流程：录入需求和缺失条件 → 检索已有规范/器件/模板 → 比较候选 → 执行确定性计算 → 生成文档草案 → 人工评审 → 验证 → 发布版本。缺少关键输入时阻止进入验证通过状态，不补造参数。

模板包含字段 schema、必填条件、单位、适用范围、章节、计算规则和检查项；模板本身版本化。计算由有版本的函数执行，记录公式版本、输入、单位、假设、精度与输出；LLM 解释结果，不充当可信计算器。

追溯链：需求 ID → 设计决策 → 选型/计算 → 来源证据 → 验证记录 → 发布版本。证据定位到具体文档版本和页码，区分引用事实、推断、待确认；器件型号相似不能视为可替换，必须比较工作范围、封装、引脚、热与降额要求。

草案、已评审、已验证、已发布分离；软件规则检查与实测验证分离。上游需求、数据手册、器件或公式变化时，标记依赖输出过期并要求重审，不自动沿用原批准。发布快照包含模板、模型标识、生成配置、来源与人工修改记录；可重放输入不等于模型输出完全可复现。

## 6. GTD、WBS、排程与效能

GTD 用于收集与澄清，WBS 用于交付物拆解，时间块用于执行安排，三者共享 task。OKR 后续作为目标关联，不引入另一套任务。复杂度、工时、精力、不确定性分别记录。

估时默认单点，可选三点估算 E=(O+4M+P)/6，约束 0≤O≤M≤P；此公式不能直接产生经验置信区间。历史建议优先同任务类型与相近复杂度，展示中位数、P75/P90、样本数和筛选条件；样本少时明确低可信并回退人工估计，不强行训练模型。

计划耗时、实际专注工时、日历跨度、等待时间分别统计。只记录叶任务实际工时；计时暂停明确、可人工修正并保留修正记录。预测保留当时快照，不能用完成后的修订估时计算准确率。

排程先检查依赖、固定时间块、可用时段、截止日与每日容量，再提供可确认的建议；允许留缓冲，不自动搬动用户安排。展示计划负载/容量、估时与实际偏差、按时完成率及分母、延期原因、返工与中断。纳入取消、缺失工时等数据质量说明，避免只分析成功任务。先做描述统计，达到稳定样本后再考虑预测；统计用于个人校准，不将任务数量等同产出价值。

## 7. Agent 权限和网络策略

默认离线可用。网络、云模型、远程工具均独立开关，关闭时在 Rust 网络出口阻断，并停止排队请求；不自动下载模型、联网补数据或上报内容。显式选择云模型时展示将发送的字段，允许脱敏与取消；离线时回退本地功能或明确不可用。

权限按运行授予：只读检索 → 生成草稿 → 指定对象写入 → 外部副作用。权限包含 workspace、对象/目录范围、工具、有效期、网络目标和资源配额。写入使用 revision 乐观锁及幂等键，提供差异预览；删除、覆盖、发布、外发与执行程序须单独确认。授权不能由检索内容或模型文本提升。

导入文档、网页与工具返回均视为不可信资料；其中的指令不能触发工具调用。工具参数经 schema 与业务校验，默认禁止任意 shell 和任意 SQL；文件路径规范化并检查目录边界、符号链接/重解析点及导出覆盖风险。取消与失败不能留下半完成写入。审计记录工具、授权、对象变化和结果，默认不写明文凭据或完整敏感提示。

## 8. 本地存储、备份、安全与性能

应用数据目录与程序安装目录分离，支持可迁移工作区。备份通过 SQLite 一致性快照并纳入所引用的不可变文档和附件，生成版本清单与哈希；不能直接复制运行中的数据库文件而忽略 WAL。至少保留多代、异盘副本；验证解压、哈希、外键和随机文档打开，并定期完整恢复至新目录。目标建议：最多丢失 24 小时数据、30 分钟内恢复，须用真实体量验证；备份失败必须可见。

凭据放系统凭据存储；默认数据库并不加密，需要时另选经验证的加密方案。日志脱敏，备份可加密且密钥独立保存。Tauri 最小 capabilities、受限 CSP、禁用不需要的远程页面和系统权限；导入限制大小、格式与路径，禁止附件自动执行。

初步验收预算（非已测结果）：在约定参考机器、1 万任务/5 万文档元数据下，常规列表交互 P95≤100ms、本地检索 P95≤300ms、冷启动≤3s；模型运行单独计量。分页、索引、虚拟列表、按需加载画布；单写入队列、短事务、受控后台索引，限制模型并发、内存和上下文。用固定数据集与冷/热缓存分别测量后调整指标。

### 9.1 本轮确认纳入的补充能力

以下五项经用户确认纳入方案，仍属于待实现能力，不表示已经完成开发。

| 能力 | 最小范围与边界 | 数据补充 |
| --- | --- | --- |
| 统一收集箱 | 快速记录文字、资料引用与附件；人工澄清为任务、知识或设计需求，也可归档；AI 分类仅作建议 | capture_item：entity_id、内容/附件引用、来源、状态、澄清目标；事务内建立目标与来源关联，重试不重复创建 |
| 数据导出与恢复中心 | 展示最近备份、失败原因、验证状态；导出 Markdown、附件与含 schema 版本的结构化数据；完整恢复先在新目录预检，由用户选择切换 | backup_manifest：快照版本、文件清单与哈希；backup_run：开始/结束、状态、错误、验证结果。便携导出与可恢复完整备份分别标识，不导出凭据 |
| 每周回顾 | 按用户时区确定周边界，汇总负载、估时偏差、延期原因、未完成项与数据缺失；用户确认下周调整 | review：周期、时区、统计截止时刻、口径版本、摘要快照、用户结论及关联任务；不复制工时事实，也不自动改排程 |
| 设计变更影响分析 | 比较版本差异，按显式依赖追踪到计算、文档、验证与任务；区分直接/间接影响，未知依赖提示人工检查 | impact_review：变更源版本、目标版本、受影响对象版本、原因、处理状态；不能把无关联理解为无影响 |
| 工程问题与验证台账 | 记录待确认参数、风险、测试失败与处理过程；关联需求、设计版本、任务和验证证据 | engineering_issue：entity_id、类别、严重性、设计版本、状态、解决说明、verification_id；与执行任务分别管理，以关联连接 |

收集箱不是第二套任务系统：尚未澄清的条目保留在 capture_item；澄清后链接真实业务对象。现有 task.inbox 仅表示已确定为任务但尚未安排的任务。

工程问题状态为 open、in_progress、pending_verification、closed；关闭需解决说明与验证证据，不能仅凭关联任务完成自动关闭。延期接受风险时记录理由及用户确认，并与验证通过区分。发布门槛检查未关闭的阻断问题及未处置影响项；AI 无权自行豁免。

影响分析复用 entity_link 和版本追溯，不引入图数据库；依赖边需记录适用版本。旧版本保留历史批准，新版本标记待重审；重审完成记录处置证据，不能批量清空过期标记来代替复核。

## 10. 待决策与优化优先级

P0：真实仓库路径缺失，无法比较已有设计。找到后另写差异记录，保留旧文档，不自动迁移或重命名代码。历史称已使用 Ant Design/Dockview，目前无文件可验证。

P0：确认 Markdown 是否必须接受外部直接编辑；若必须，需先实现冲突检测与恢复，不能同时把 SQLite 正文和文件正文都当权威。

P0：先定备份边界、实体约束、估时快照与工时口径，再做 AI 和图表；否则统计与追溯会建立在不一致数据上。

P1：MVP 削减自由白板、复杂自动排程、OKR、向量库、自主 Agent 和 Git 自动提交。一个应用服务层、一个数据库足以验证核心价值；SQL 关系先于泛化图引擎。

P1：许可证、版本兼容和维护状态在获得锁文件后逐项核验；先接入一种模型运行方式与一个工程模板，避免多运行时维护负担。

P1：工程 AI 的首个交付应是可审阅的证据化草稿，优先建设模板/计算/审核链，随后再做多步自动化。

P2：跨设备同步、外部知识编辑器、商用组件、数据库加密、模型选择、工程导出格式及具体性能参考机器仍待选择。没有现有设计可比较，因此当前没有已证实的实现冲突；这里的未决项不是用户已批准的决策。
