# 共用应用服务最小契约

日期：2026-11-03｜状态：P1 设计草案；尚未实现生产接口

## 调用者与复用边界

桌面 commands、外部 CLI 适配器、应用内 Agent 调用同一套 Rust 应用服务。应用内 Agent 直接调用服务，不经过 shell 或 CLI。每个入口负责输入解析与身份传递，业务服务统一负责授权、状态、事务和版本；不另建 CLI 专用任务服务或 Agent 专用知识库。

Worktrace 已有 task、timer、history、stats、backup 命令优先保留语义、类型、错误与版本机制。新增知识操作目前仅按 read/save_version 概念设计；小样 Store 与 JSON 进程是验证工具，不承诺原样成为公开协议。正式 DTO 核对旧协议后再定义一次，前端/CLI 从同一语义映射。

## 请求与结果

| 事项 | 约束 |
| --- | --- |
| 身份与授权 | 在可信入口建立调用上下文；不得接受模型或普通请求体自称管理员。授权绑定工作区、操作、对象范围和有效期 |
| 版本 | 写请求校验 expected_data_epoch 与对象版本；结果携带权威 epoch/revision。对象版本、内容版本、全局 revision 不能互换 |
| 幂等 | 新建、采纳等可重复提交操作携带幂等键；同键同内容返回既有结果，同键异内容拒绝。幂等记录与业务写入同事务 |
| 错误 | 沿用现有错误类别与握手约定，新增原因只在语义确实缺失时引入；外层区分传输失败与业务拒绝 |
| 查询 | 明确分页、时区、范围及版本；前端过滤迟到响应。历史正文按显式内容版本读取，不隐式改为最新 |
| 内容 | 正文和附件先持久化并核验，再事务更新引用；冲突不覆盖草稿。失败遗留文件不能自动成为有效版本 |
| 副作用 | 服务校验权限后才执行，非交互调用缺权限立即拒绝；用户确认生成的授权不能由模型文本替代 |
| 审计 | 记录调用者、操作、对象、结果与版本；凭据和完整敏感正文不进入常规日志 |

CLI stdout 仅输出版本化结构化结果、stderr 输出诊断，业务错误与传输失败的退出码在 CLI 实施时定稿。所有入口遵循后端网络开关，模型开关不等于网络授权。

## 运行态与并发

保留 Worktrace 唯一计时协调器和短事务串行提交思路。桌面与外部 CLI 访问同一权威运行态，CLI 不自行打开生产库另起协调器。独占维护操作有明确维护态；模型、索引、附件和长计算不持业务锁，完成后按输入版本重验再提交。

## 接口复用评审

新增入口前检索 src/ipc.ts、types/ipc.ts、Rust commands 和 services，记录已有语义是否适用。纯转发由必要平台入口承担，不叠加 Facade/Manager。不同业务含义不为复用强塞进同一命令，例如通用资料澄清不等同于任务状态跃迁。

## 接入验收

同一操作从桌面、CLI 或 Agent 进入应产生相同业务结果和拒绝条件；默认只读权限、版本冲突、重复提交、恢复换库后旧身份、网络关闭、取消和超时须分别验证。入口适配测试不能代替服务闭环，服务模拟不能代替实际桌面和本机 IPC 测试。

下一步：对照 Worktrace 的实际 DTO 确定最小对象/任务映射，先接桌面知识保存路径；CLI 与 Agent 尚不扩展为当前实现范围。
