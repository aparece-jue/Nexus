# 架构决策记录（ADR）约定

目的：保存重要技术选择的背景、替代方案、代价和重新评估条件。总体设计中的候选技术不因出现在文档中而自动成为已采纳决策。

编号使用 `0001-主题.md`，状态采用 proposed、accepted、superseded、rejected。记录内容至少包括：日期、状态、问题与约束、比较过的方案、选择及理由、影响与代价、验证证据、重新评估条件、相关方案和替代记录链接。

只有明确确认的决定标记 accepted；尚无验证证据时如实写明。已采纳决策发生变化时新增记录并链接旧记录，不抹去历史理由。产品范围确认不等同于具体依赖或许可证已批准。

首批待建立的决策：

- 真实代码仓库与现有技术栈对齐。
- SQLite、不可变文档文件与外部编辑的权威边界。
- Rust 数据库访问库及迁移方案。
- 完整备份格式、恢复切换与便携导出边界。
- UI、画布、日历组件的精确版本与许可证。
- 模型运行方式、网络出口与 Agent 授权边界。

每项在实施前补充实际候选和证据；目前不预填未核验的结论。
