# ADR 0003：桌面与 CLI 共用业务服务

日期：2026-11-03｜状态：proposed（建议基线，正式协议随实现确认）

## 背景与选择

用户希望预留 CLI，便于其他 Agent 调用，并考虑后续设备内集成。两种交互可以共存：Nexus 桌面提供人工工作台与可选内置 Agent；CLI 提供自动化入口，复用同一应用服务，不建设第二套任务、存储或授权规则。

现有 prototypes/knowledge-store/src/main.rs 是测试专用连接，仅验证 read/save 到真实存储，不能直接成为生产 CLI：它缺少完整身份、授权、运行态协调、错误契约及接口兼容保证。

## 建议边界

调用方向：桌面 commands / CLI 参数解析 → 共用 Rust 应用服务 → 领域规则、权限与存储。CLI 只转换输入输出，不包多层 Manager，不新增业务同义命令。先检查 Worktrace 已有请求与响应，保持语义、版本、错误及幂等规则一致。

正式 CLI 以版本化 JSON 请求/响应为主要机器接口；stdout 只放结果，诊断进 stderr，定义退出码。请求可从 stdin 读取，避免敏感文本出现在命令行历史。支持按需分页、明确查询范围及运行时资源限制，写入携带对象版本和幂等信息。命令名称和 schema 尚未锁定，实施时以共用契约生成或映射，不提前维护两份 DTO。

## 运行态协调

桌面和 CLI 不能各持一套计时协调器。应用运行时，CLI 通过经认证的本机 IPC 请求唯一运行态；Windows 可评估 named pipe，其余平台按需实现本地 socket，不默认开放 TCP 端口。

无桌面时，可由按需启动的 headless 主进程承载同一运行态和服务；是否持续驻留及生命周期在专门小样后决定。CLI 一次调用退出不能让正在执行的计时静默丢失。离线直接开库只适合明确维护态/独占场景，不作为绕过应用服务的后门。

## Agent 与权限

CLI 不因本机调用就自动拥有全部权限。调用身份、工作区范围、可用工具与网络目标均受控；默认只读，写入/删除/发布/外发按已授予范围处理。非交互模式缺少授权时返回结构化错误，不等待不可见的确认框，也不自动同意。

CLI 与内置 Agent 都使用相同审计、授权和冲突校验；网络关闭仍由后端出口约束。未来可为 CLI 增加薄 MCP 适配入口，但在真实调用需求明确前不引入完整 MCP 服务或通用 Agent 平台。

## 分阶段落实

当前只预留共用服务边界，继续完成桌面闭环；正式 CLI 先提供只读检索、对象读取与状态查询，再扩展受控创建/修改。进入真实外部 Agent 调用前验证 JSON 契约、幂等、权限拒绝、并发、桌面/CLI 状态一致、恢复换库、超时和进程退出行为。

## 待决策

“设备内部”暂按同机桌面/headless 部署理解；若指无桌面 Linux 嵌入式硬件，需确认架构、内存、存储、系统与更新方式后验证兼容性。独立 CLI 是否随 MVP 发行由使用场景决定，不扩大当前首版功能。
