# ADR 0002：Nexus 整体框架基线

日期：2026-11-02｜状态：accepted（架构方向；依赖版本仍待验证）

## 决策

Nexus 采用本地优先的一体化桌面应用，技术主线为 Tauri 2、React、TypeScript、Rust 和 SQLite。采用模块化单体，不建设独立后端服务器、微服务或通用 Agent 平台。

### 业务模块

1. 工作台与收集箱：快速录入、澄清、导航和全局搜索入口。
2. 知识：文档、器件、规范、模板、资料来源和内容版本。
3. 事务：项目、任务、WBS、依赖、计划、计时与工时修正。
4. 工程设计：需求、方案、选型、计算、评审、验证、问题与变更影响。
5. 回顾分析：统一统计、历史估时基线、容量预览、成果与报告快照。
6. Canvas：对象卡片、架构图与自由白板展示。
7. AI 辅助：上下文选择、检索、草拟、模型适配和受控工具调用。

共享基础设施包括对象身份与关系、版本和审计、文件存储、全文索引、备份恢复、权限与网络策略。共享基础设施不拥有具体领域状态机；业务模块通过应用服务协作，不互相直接写对方的数据表。

### 技术职责

React 负责交互与展示，前端状态仅是后端事实的缓存；Tauri commands 负责类型化调用边界；Rust services 编排事务与权限，domain 保存业务规则，storage 管理持久化，platform 适配时钟、文件和系统窗口。长索引、模型推理、附件处理与计算在业务锁外执行，提交时重新校验输入版本。

SQLite 保存结构化事实和版本索引，不可变本地文件保存正文及附件。Nexus 是统一写入入口；搜索和统计缓存可重建。画布节点引用稳定对象 ID，画布布局与业务关系分别存储。导入其他应用的数据需要预览、去重和冲突检查，不建立双权威正文。

Agent 通过与人工操作相同的应用服务访问数据，默认只读/草稿，不直连 SQL；修改、外发和执行按范围授权。核心功能不依赖网络或模型，网络开关在后端出口执行。

### 自研与集成

自研对象关系、事务状态、工时口径、工程追溯、回顾逻辑和 Agent 权限；复用数据库、编辑器、图表与画布组件。Ant Design 作为主 UI 组件方向；Dockview、React Flow、Excalidraw、ECharts、FullCalendar 仍按实际阶段验证后引入，不一次安装全部依赖。

Worktrace dev 是事务、计时、恢复与同步的候选代码来源，不自动视为 Nexus 底座已经迁入。迁入前固定提交并复验，统一状态机、单位、对象 ID 和备份边界。禁止将其外部 Agent 负责所有正文处理的边界直接套用到 Nexus。

## 实施顺序

先确定依赖小样与数据契约，再交付知识/任务/工时/回顾/备份闭环；随后加入 Canvas 与工程追溯，再接入 AI 和复杂排程。研发资料在 research，业务开发在 dev，稳定发行在 main。

## 未锁定项与重新评估条件

编辑器实现、Rust 数据库库、组件精确版本、模型运行方式、细化表结构、任务状态及时间单位须在小样和 Worktrace 对齐后单独记录。许可证、打包、性能与迁移实验未通过时，可替换组件；若改变统一来源、领域边界或存储权威，必须新增 ADR。

本决策是框架基线，不代表代码已经实现或性能已验收。
