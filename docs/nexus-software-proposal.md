# Nexus 一体化个人工程工作平台软件方案

版本：V1.0｜日期：2026-11-02｜状态：产品与软件设计方案，待实现

整体框架已确立为 [ADR 0002：架构基线](architecture/decisions/0002-architecture-baseline.md)。后续实现以此为准，具体依赖版本与数据契约通过实验和评审补充。

最新开发约束见 [整体框架基线](architecture/framework-baseline.md)。Nexus 已建立 Git 仓库及 research/dev/main 分支；下文“未发现 Git 仓库”属于初次检查背景，当前尚无应用代码。计时单位以新基线的毫秒精度契约为准。

## 1. 建设目标

Nexus 面向个人工程研发与日常工作，将知识、设计、任务、时间和 AI 放在一个本地桌面平台中，形成“收集资料—理解知识—形成设计—组织执行—验证复盘”的闭环。

主要解决四个问题：资料分散、设计依据难以追溯、任务与成果脱节、估时缺乏历史反馈。核心价值是统一数据与工作流程，不以简单叠加工具数量作为目标。

本方案明确采用一体化路线：Nexus 是核心数据的管理与编辑入口。Obsidian、Anytype、AppFlowy、Heptabase 等作为产品参考和可选导入来源，不是必需运行依赖。专业电路绘制、仿真和代码开发仍由专业软件完成，Nexus 管理其成果引用、版本和验证证据。

本文件描述目标产品；具体架构约束参见 [总体设计](architecture/nexus-design.md)，场景验收参见 [验收标准](acceptance-scenarios.md)。目前指定目录只有设计文档，未发现可验证的 Tauri/React/Rust 源码或 Git 仓库，不能将以下能力视为已有实现。

## 2. 设计原则

- 统一来源：同一对象拥有稳定 ID，各视图引用同一份业务数据。
- 本地优先：核心知识、任务、设计和统计断网可用，AI 不是启动前提。
- 模块独立：知识、事务、设计各自拥有业务规则，通过明确关系互通。
- 工程可信：区分事实、推断、待确认、计算与实测结果，保留版本依据。
- 用户掌控：Agent 的写入、网络和外部操作受到授权约束。
- 渐进实现：先完成可日常使用的闭环，再扩展画布与复杂自动化。

## 3. 产品功能

| 模块 | 主要功能 | 典型产出 |
| --- | --- | --- |
| 工作台与收集箱 | 快速录入、最近项目、待处理事项、搜索、来源记录、澄清与归档 | 可关联的任务、知识或设计需求 |
| 工程知识库 | Markdown 编辑、附件预览、标签、双向关联、器件参数、规范、模板、版本 | 知识条目、器件档案、参考设计 |
| Canvas | 对象卡片、分组、连线、缩放、子画布；后续支持自由绘图 | 研究白板、工程架构图 |
| 项目与事务 | GTD、WBS、任务依赖、状态、估时、时间块、实际工时 | 执行计划与工作记录 |
| 效能分析 | 预计/实际对比、任务类型统计、容量预览、延期原因、每周回顾 | 可解释的个人历史基线 |
| 工程设计 | 需求、模板、方案比较、选型、计算、评审、验证、问题台账、变更影响 | 可追溯设计版本 |
| AI 与 Agent | 指定上下文问答、带来源草拟、工具提案、受控执行、运行审计 | 可审阅的建议与草稿 |
| 数据管理 | 导入导出、完整备份、完整性检查、恢复预检、设置 | 可迁移且可恢复的工作区 |

### 3.1 知识与 Canvas

文档、器件、项目、任务和设计都有独立身份。对象可显示为页面、表格行、看板卡片或 Canvas 卡片；从任一入口编辑均调用同一业务服务。画布只保存对象引用及位置、尺寸、分组等展示信息，不另存一份可独立修改的正文。

允许临时文本卡片辅助思考，转为知识对象后保留来源。视觉连线默认仅表达展示关系；建立“依赖”“满足需求”等业务关系时必须显式选择类型并通过校验，避免随手画线改变工程逻辑。

知识模块提供基本编辑和资料组织，不以第一版复刻全部笔记软件功能为目标。导入外部资料采用预览、去重及冲突提示，不支持外部编辑器无约束双向写入。

### 3.2 事务与个人效能

收集箱处理尚未澄清的信息；确认后转为真实任务或知识。项目通过 WBS 拆解，只有叶任务登记工时，父任务汇总显示。预计时长、实际专注工时、等待和日历跨度分别记录。

普通任务单点估时，探索任务可用三点估算。历史分析展示中位数、分位数、样本数和筛选条件；样本不足时回退人工估计。保留执行前估时快照，防止事后修改掩盖偏差。

首版提供可用时间、任务负载与容量对照，用户手动安排时间块。后续再根据依赖、截止日、精力和缓冲给出排程建议；确认后才改变计划。每周回顾展示未完成项、偏差、延期原因及数据缺失，由用户决定下周调整。

### 3.3 AI 工程设计

标准流程为：需求输入与缺项检查 → 检索已有知识和模板 → 候选比较 → 确定性计算 → 文档草稿 → 人工评审 → 验证 → 发布。

首个场景只选择一种真实硬件设计模板。模板包含字段类型、单位、必填条件、适用范围、章节、计算规则和检查清单。模型提供分析和文本，计算工具记录公式版本、输入、假设、单位及输出；缺少关键参数时不能自动补造。

追溯链覆盖需求、决策、器件、计算、来源与验证。修改上游版本后展示直接/间接影响，相关成果进入待重审状态。工程问题关闭需要处理说明与验证证据，关联任务完成不能自动证明问题解决。发布检查阻断问题和未处置影响项，Agent 不能自行批准。

## 4. 交互与信息架构

左侧提供工作台、收集箱、知识、项目、Canvas、工程设计、分析和数据管理入口；中央为文档、表格、看板或画布；右侧按需显示对象属性、关联、来源和 AI 面板。全局搜索与快速录入减少在模块间切换。

项目页面集中展示目标、资料、设计、任务、工时与风险，但各模块仍维护自己的事实。AI 面板明确显示正在使用的资料范围、模型和网络状态，保存回答时选择目标对象与版本。

## 5. 技术架构与工具边界

采用模块化单体：React/TypeScript 界面 → 类型化 Tauri commands → Rust 应用服务 → 领域规则与权限校验 → SQLite 和本地文件。Agent 与人工操作共用应用服务，禁止绕过校验直接写数据库。

| 层次 | 候选技术 | 自研职责 |
| --- | --- | --- |
| 桌面与界面 | Tauri 2、React、TypeScript；Ant Design、Dockview 按需引入 | 工作台、业务页面、统一对象交互 |
| 文档与画布 | Markdown 编辑器待选；React Flow、Excalidraw 为候选 | 对象引用、关系语义、版本与序列化 |
| 任务与分析 | 基础列表优先；FullCalendar、ECharts 按阶段选择 | 状态、WBS、估时口径、排程与统计规则 |
| 业务与存储 | Rust、SQLite、FTS5、本地文件 | 事务、一致性、迁移、追溯、备份恢复 |
| AI | 可选 Ollama 或 llama.cpp、可插拔云模型接口 | 上下文、计算工具、权限、审核与审计 |

不自研数据库、通用模型或完整绘图引擎；不在初期引入微服务、图数据库、向量服务或多套模型运行时。组件是嵌入式能力，Nexus 是用户使用的统一应用。

所有依赖仍须核对精确版本、许可证、传递依赖、维护状态、目标平台兼容性和打包体积。产品功能参考不代表允许复制源码；开源程序和模型权重也需分别审查。

## 6. 数据设计

SQLite 保存结构化事实、对象关系和版本索引；不可变文件保存正文与附件。两者由 Nexus 协调写入；全文索引、缩略图及统计缓存可重建。统一来源是明确每类数据的权威位置，不要求把所有二进制内容放入数据库。

核心对象包括 entity、capture_item、knowledge_item、component、project、task、estimate、time_entry、time_block、canvas、design_revision、requirement、decision、calculation、verification、engineering_issue、review 和 agent_run。

entity_link 记录有类型的业务关联，document_version 和 evidence 记录内容版本与来源。Canvas 节点引用 entity ID；依赖分析引用对象版本。所有时间统一保存 UTC，展示保留时区；时长统一秒；工程量必须带单位与容差。

写入使用事务、外键与 revision 校验。文件先落盘并核对哈希，再事务切换版本指针；崩溃遗留文件由恢复扫描处理。迁移前创建快照，失败时停止写入，避免带着半完成 schema 继续运行。

## 7. 离线、权限与可靠性

默认关闭不必要的网络功能，不自动上传内容、下载模型或进行遥测。开启云模型时展示发送范围，允许脱敏和取消；关闭网络后阻断新的请求并停止排队发送，已经发出的内容无法撤回。无模型时核心功能正常使用。

Agent 权限按运行、对象、目录、工具、网络目标和有效期限定。默认只读或生成草稿，写入通过差异预览和业务校验；删除、覆盖、发布、外发及程序执行单独确认。不可信资料中的指令不能提升权限。凭据使用系统凭据存储，日志与审计脱敏。

完整备份使用 SQLite 一致性快照，包含引用文件、版本清单与哈希；保留多代并建议异盘副本。恢复在新目录预检后由用户选择切换。便携导出与完整备份分开标识，避免用户误认为导出文件能恢复全部工作区。备份失败、文件损坏和恢复检查结果必须可见。

性能通过分页、索引、虚拟列表、懒加载画布和后台长任务控制。具体性能预算沿用总体设计，须在固定参考机器和数据集上验证，不能视为已达到指标。

## 8. 实施路线

| 阶段 | 交付范围 | 验收重点 |
| --- | --- | --- |
| 0 技术确认 | 找回/确认代码仓库，确定编辑器与数据库库，验证迁移和打包，记录 ADR | 真实依赖、许可证与基础小样可审查 |
| 1 可日用 MVP | 统一对象、收集箱、基础知识编辑、项目任务、估时工时、简单统计、每周回顾、搜索与备份恢复 | 断网完成一周工作闭环，数据可恢复 |
| 2 视觉与工程基础 | 对象 Canvas、器件与规范、单一设计模板、计算、证据、问题台账与影响分析 | 真实设计可追溯，上游修改触发重审 |
| 3 AI 辅助 | 指定上下文问答、引用、设计草稿、受控工具、可选模型 | 无依据输出可识别，越权与注入被阻止 |
| 4 增强优化 | 日历、排程建议、历史校准、自由白板、导入格式扩展 | 操作成本降低，性能和数据口径达标 |

首版不包含多人协作、云同步、插件市场、完全自主 Agent、自动设计发布或完整 EDA 能力。各阶段按实际场景验收后进入下一阶段，暂不在缺少代码和人力评估时承诺工期。

## 9. 主要风险与控制

Worktrace 候选基础及分版本映射详见 [复用评估](architecture/worktrace-reuse-review.md)。吸收人工/机器/等待分列、AI 预计/用户计划/实际分离、不可变回顾报告和成果证据设计；互动图表、HUD、能力模型及自动升级按阶段评估，不直接继承旧项目的待议范围或工期。

| 风险 | 控制措施 |
| --- | --- |
| 一体化范围不断膨胀 | 围绕核心场景排序，组件按需加载，阶段验收限制范围 |
| 多视图形成重复数据 | 所有视图引用统一对象，明确画布布局与业务事实边界 |
| AI 生成错误工程结论 | 来源、确定性计算、人工评审、验证与发布门槛分离 |
| 工时不足导致统计误导 | 展示样本量、缺失数据与口径，优先描述统计 |
| 本地数据损坏或设备丢失 | 多代异盘备份、校验、恢复演练，凭据与备份分离 |
| 依赖许可或成熟度不符 | 实施前核对官方许可与精确版本，保留替代组件接口 |
