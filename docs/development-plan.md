# Nexus 开发执行计划

日期：2026-11-02｜状态：执行基线，功能尚未实现

依据：[软件方案](nexus-software-proposal.md)、[架构基线](architecture/decisions/0002-architecture-baseline.md)、[Worktrace 评估](architecture/worktrace-reuse-review.md)。

## 开发方式

有限架构先行，按完整场景交付可运行版本。先确认高成本的数据与权限边界，不预建全部空模块；每阶段包括界面、持久化、异常处理、必要测试和演示证据。阶段完成以验收为准，不以目录、代码量或测试数量为准。

研发方案和验证记录保存在 research，应用源码在 dev，main 仅接收满足发行条件的版本。每轮记录提交版本、改动范围、验证及遗留项；只将适用规格同步到 dev，不将所有实验资料整体合入发行源码。

## 阶段与依赖

| 阶段 | 主要任务 | 交付物 | 退出条件 |
| --- | --- | --- | --- |
| P0 基础复验 | 固定 Worktrace dev 提交，在隔离副本复验构建、计时、恢复、统计、备份；检查依赖与许可；验证编辑器、文件版本和对象引用小样 | 复验报告、复用清单、技术决策与风险 | 明确可复用模块及边界，关键小样可运行；不以历史通过记录替代本次证据 |
| P1 数据契约 | 确定对象 ID、关系类型、任务状态、时间单位、版本冲突、文件权威、接口错误、迁移与备份格式 | 最小 schema、接口契约、ADR、异常验收项 | Worktrace 与 Nexus 差异有明确映射；创建/修改/归档/恢复规则一致 |
| P2 应用基础 | 在 dev 建立 Tauri/React/Rust 工程与主 UI；引入必要依赖；接工作区、数据库迁移、文件存储、统一调用边界 | 可启动桌面程序及最小数据访问链 | 重启保留对象；迁移失败安全停止写入；日志无凭据；无需网络或模型 |
| P3 首个闭环 | 项目、收集箱、基础 Markdown 编辑、资料与任务关联、单点估时、可靠计时/修正/恢复、简单回顾、完整备份恢复 | 内部可日用版本 | 断网完成项目→资料→任务→估时→计时→回顾→新目录恢复，覆盖异常退出与损坏备份 |
| P4 真实试用 | 至少两周本人使用，记录漏记、忘停、修正、录入负担与回顾价值；修复阻断问题 | 试用记录、缺陷优先级、更新后的工作量估算 | 无未处置的数据丢失或工时误算问题；根据证据确定下一阶段范围 |
| P5 Canvas | 对象卡片、分组、视觉连线和显式业务关联，持久化布局；按需增加架构图视图 | 资料与项目视觉工作区 | 同一对象不同视图修改一致，移动卡片不改变依赖，旧布局可迁移 |
| P6 工程设计 | 一个真实模板，需求、选型、确定性计算、来源、评审、验证、问题、版本与影响分析 | 单场景可追溯设计闭环 | 结论可追到来源与输入；变更触发重审；阻断问题存在时不得发布 |
| P7 AI 辅助 | 上下文选择、模型适配、带引用草稿、受控计算工具、差异确认、审计 | 可选 AI 增强版本 | 无模型仍可使用；引用可校验；越权、资料注入、版本过期及取消路径有验证 |
| P8 分析增强 | 后端统一聚合、下钻图表、估时校准、容量与排程建议；按使用反馈选 HUD/热键 | 个人效能增强版本 | 人工/机器/等待分列；缺失与样本可见；调整排程需确认 |
| P9 发行硬化 | 迁移兼容、故障与长期运行、安装包、升级前备份、签名策略与版本说明 | 发行候选与 main 稳定版本 | 满足发布清单；恢复演练成功；已知局限明确；自动更新仅在有需要时另行接入 |

P0→P1→P2→P3→P4 为首条主线。P5～P8 是默认推进顺序，可按试用结论调整，但 AI 不得绕过来源、权限和版本基础。可靠性从 P2/P3 开始建设，P9 执行完整发行验收，并非到发行阶段才做备份和迁移。

## 首批具体工作

1. 记录 Nexus 与 Worktrace 的分支/提交和只读检查结果，不修改旧项目。
2. 创建隔离 Worktrace 副本，先检查现有工具链与缓存；缺失依赖需安装时单独说明，不在复验前直接复制整个项目。
3. 依次验证基础构建、计时和时钟异常、恢复、统计、备份；区分自动化、模拟故障和真实系统测试。
4. 选择首批迁入代码，保留相关测试和来源记录；检查 UI 依赖和平台耦合，排除无关演示与生成产物。
5. 在最小 schema 中确定 ID、状态、时间精度和版本机制，验证任务与知识对象关联。
6. 验证最小 Markdown 编辑与不可变内容写入、应用崩溃后的引用一致性，再开始完整桌面闭环。

## 首版范围约束

只支持一个本地工作区的基本使用路径、简单知识编辑、项目任务、单点估时、计时恢复、基础搜索与周回顾、手动备份恢复。核心工时明确人工投入，与机器和等待分类不混算。

暂不加入自由白板、复杂多任务并行计时、加权标签、能力评分、自动排程、通用 Agent、多人协作、云同步或插件市场。对象与存储契约为后续扩展提供边界，不提前实现这些功能。

## 每轮完成标准

- 场景可演示，数据真实持久化，失败状态可理解且可恢复。
- 新增规则有对应必要验证；低风险纯展示修改不机械增加测试。
- 受影响的构建、契约与回归检查通过，未通过项明确记录。
- 文档标明实际实现状态与遗留项，禁止把计划当交付。
- 提交范围清晰，工作区保留用户文件，稳定发行通过 dev 晋级 main。

## 估算规则

暂不承诺总工期。P0 后提供首版任务拆分与区间估算，P3 后依据实际迁入成本和缺陷修正，P4 后再估算完整产品；Worktrace 行数、历史提交数和旧工期不直接换算为 Nexus 工期。P4 的两周是使用观察窗口，不是整体开发期限。
