## 实际原生操作与观察

使用computer-use在合成任务“首轮验收任务-1117”上执行：

1. Inbox任务选中后开始计时禁用。通过状态按钮转Ready，重新选中后开始计时可用。
2. 点击开始：面板显示计时中，已确认0，暂计从0增长；观察到暂计25秒、48秒。
3. 点击暂停：状态变为已暂停，已确认显示48秒，暂计0。额外等待5秒后仍是48秒，暂停不累计。
4. 点击继续：回到计时中；随后观察已确认48秒＋暂计23秒＝面板总计1分11秒。显示按秒取整，不据此宣称毫秒精度人工测量。
5. 点击结束：后续状态刷新显示开始计时入口，活动会话占用释放。当前没有历史列表，本轮未从UI读取结束会话最终精确时长。
6. 再次开始合成会话，观察暂计22秒；不点击结束，Alt+F4正常退出应用。重启后显示中断待处理，确认及暂计均0；该会话开放区间未自动确认。
7. 点击结束中断会话后恢复无活动会话的开始入口。待确认区间保留是后端自动化已覆盖的事实，本轮UI没有历史查询入口，未声称通过界面检查了历史内容。

这是“正常退出时仍有开放会话”的重启恢复，不是杀进程/断电故障测试。没有触发休眠、锁屏或修改系统时钟。期间控件定位曾返回coordinate input geometry is unavailable，重新激活/观察截图后执行成功；检测到用户交互后先重观察。没有绕过权限或代操作系统设置。

## 局限与后续

本轮原生只验证短时正常流、暂停排除及重启恢复。未覆盖长时间运行、休眠/锁屏、强制退出、真实时钟跳变、多个新进程争用、跨日与时区、每日聚合、补录修正、待确认历史处置和备份恢复。正常结束后活动面板清空，目前缺少结束结果摘要/历史入口，是后续易用性缺口。
